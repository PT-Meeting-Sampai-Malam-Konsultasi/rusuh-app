# Firebase App Distribution (Android demo builds)

The `distribute` job in `.github/workflows/android-build.yml` sends a **debug APK of the staging or production flavor**
to testers on every push to `main` (staging) and on manual dispatch (Actions > Android Build > Run workflow, input
`flavor`: `staging` or `production`):

- **staging** (default for pushes): `-PmockApi=false`, launcher name "Rusuh Staging", the app talks to the staging API
  `https://api.rusuh-tiket.web.id/v1`.
- **production**: launcher name "Rusuh", always the production API (the production flavor ignores `-PmockApi` and
  `-PbackendMode`).

**No mock and no stub build is ever distributed.** The job fails before the upload if the generated build config is not
`Staging`/`Production` for the chosen flavor, has a mock API override or the stub backend mode. Use a local build
(`-PmockApi=true` with Mockoon, or `-PbackendMode=Stub`) for those.

The release note is generated by the workflow, for example:

```
[Staging] merge from: main
last commit: FR-05-M6 (#150): Validate attendee NIK while typing with a debounced API call (c4bec00)
```

`merge from` is the branch the run is on; `last commit` is the commit message (for a merge commit, the pull request
title) and its short hash. The note makes no claim about which screens are real.

Every build gets `versionCode` = the workflow run number (`-PversionCode`), so testers can tell builds apart.
iOS is not distributed: a device install needs a signed build and the paid Apple Developer Program.

## Flavors

| Flavor | Task | Launcher name | API |
|--------|------|---------------|-----|
| staging | `assembleStagingDebug` | Rusuh Staging | Staging (or Mock/Stub in debug) |
| production | `assembleProductionDebug` | Rusuh | Production always |

The `build` job builds both flavors (`assembleDebug`); the `distribute` job builds only the staging flavor.

## One-time setup
1. Firebase project `rusuh-app` with the Android app `com.rusuh.app.android`; App Distribution enabled.
2. A tester group. The workflow uses the alias `rusuh-devs`; to use another alias set the repository variable
   `FIREBASE_TESTER_GROUPS` (comma separated aliases). The alias is shown under App Distribution > Testers & Groups.
3. A Google Cloud service account for project `rusuh-app` with the role **Firebase App Distribution Admin** and a JSON key.
4. In Settings > Secrets and variables > Actions:
   - secret `FIREBASE_SERVICE_ACCOUNT_JSON`: the whole JSON key;
   - `FIREBASE_APP_ID`: the Android app id (`1:...:android:...`, Firebase Project settings > Your apps). It is not a
     secret: a repository **variable** is enough (a secret with the same name also works; the variable wins).
Until both exist the job only prints a notice and passes.

## google-services.json and Firebase Analytics

The `google-services.json` file is required to enable Firebase Analytics. It must NOT be committed to the repository.

### How to get the file
1. Go to Firebase Console (https://console.firebase.google.com).
2. Open the project (e.g. `rusuh-app`).
3. In Project settings (gear icon) > Your apps, find the Android app.
4. Download `google-services.json`.
5. Place it in `androidApp/google-services.json`.

### CI setup
Add the repo secret `GOOGLE_SERVICES_JSON` with the entire content of the file. The build and distribute jobs write
it to `androidApp/google-services.json` before the build when the secret exists.

### Builds without google-services.json
The `com.google.gms.google-services` plugin is only applied when `androidApp/google-services.json` exists. Without it:
- The build succeeds.
- Firebase Analytics is not initialized (the implementation guards with a try/catch around `FirebaseApp.getApps()`).
- The `ConsentAwareAnalytics` wrapper forwards to a no-op implementation.

## Viewing events in DebugView

1. Connect a device or emulator.
2. Enable debug mode:
   ```
   adb shell setprop log.tag.FA VERBOSE
   adb shell setprop debug.firebase.analytics.app com.rusuh.app.android
   ```
3. Open the app. Grant analytics consent when prompted.
4. Watch `adb logcat` for `Logging event`.
5. In Firebase Console > Analytics > DebugView, select the device.
6. Events appear in real time.

To disable debug mode:
```
adb shell setprop debug.firebase.analytics.app .none.
```

## Notes
- The key file is written to the runner's temp dir with owner-only permissions and removed when the step ends.
- Rotate the key: create a new JSON key for the service account, update the secret, delete the old key in Google Cloud.
- Release notes carry the short commit id and the first line of the commit message.
