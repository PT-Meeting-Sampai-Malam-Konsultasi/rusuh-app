# Runtime language switch

The selected language lives in `AppLanguageState`, backed by `AppPreferences` and exposed as a `StateFlow`. The app root provides it through `LocalAppLanguage`, applies the platform locale override synchronously, and keys the navigation tree by language so Compose recomposes with fresh resource lookups. Header toggles on the app screens update the same state, including sign-in. The active language also supplies `Accept-Language` on each API request, and the stored choice is restored at startup.

On Android, `applyPlatformLanguage` calls `android.os.LocaleList.setDefault()` before composition, ensuring that `androidx.compose.ui.text.intl.Locale.current` returns the selected locale when CMP Resources resolves `stringResource`/`pluralStringResource`. The Indonesian resource folder uses `values-in` (Java's ISO 639-1 code) not `values-id` (BCP 47), because Android's `Locale.getLanguage()` returns "in" for Indonesian. On iOS, `applyPlatformLanguage` writes `AppleLanguages` to `NSUserDefaults`; immediate runtime switching remains best effort and may require an app restart.
